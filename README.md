## 1. Overview

VoxDesk AI includes a controlled public browser voice demonstration using server-side provider integrations and fictional business workflows. Live telephone calling, external CRM sync and real calendar integration require client-specific credentials and deployment configuration.

The application demonstrates how an intelligent AI voice receptionist can handle inbound calls, qualify sales leads, check appointment availability, escalate urgent legal inquiries, and record structured CRM activity.

---

## 2. Voice & Intelligence Pipeline Architecture

- **Realtime STT:** ElevenLabs Scribe Realtime (via server-issued single-use tokens) or Browser SpeechRecognition fallback.
- **Language Inference:** OpenRouter LLM (`lib/providers/openrouter.server.ts`) with Zod-validated structured outputs or server deterministic state fallback.
- **Text-to-Speech:** ElevenLabs Flash TTS (`lib/providers/elevenlabs-tts.server.ts`) with server-issued `responseId` vouchers or Browser SpeechSynthesis fallback.
- **Calendar Provider:** `DemoCalendarProvider` (Fictional Demo Calendar slot reservation).
- **CRM Provider:** `DemoCRMProvider` (VoxDesk Demo CRM record creation).

---

## 3. Public Security & Abuse Controls

1. **API Key Isolation:** All provider API keys reside strictly on the server (`import "server-only";`).
2. **Response Voucher System:** The public `/api/demo/tts` endpoint accepts only single-use `responseId` references generated by `/api/demo/respond`. Arbitrary browser-submitted text is rejected.
3. **Session Quotas:** Enforced server-side (`IDemoSessionStore`) with maximum 3 minutes, 6 turns per call, 600 user characters per turn, and 350 agent characters per turn.
4. **Rate Limiting:** Maximum 3 sessions per IP per 24 hours, minimum 60-second cooldown, maximum 5 global concurrent sessions.
5. **Global Provider Kill Switch:** `DEMO_LIVE_PROVIDER_KILL_SWITCH` allows instant transition to guided deterministic mode without interrupting site availability.

```bash
npm run dev
```

```bash
npm run test
```
