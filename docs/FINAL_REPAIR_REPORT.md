## 3. Detailed Architectural Repairs

1. **Environment Security**: Clean `.env.example` with strict placeholders only. `lib/config/env.ts` enforces Zod startup validation.
2. **Session Store (`IDemoSessionStore`)**: Abstracted interface backed by `RedisDemoSessionStore` (Upstash) and `MemoryDemoSessionStore`. Browser cookies contain only opaque signed IDs verified with HMAC timing-safe comparison.
3. **Atomic Rate Limits & Abuse Control**: Enforces max 3 sessions/IP/24h, 60s cooldown, max 5 global concurrent sessions, max 75 global daily sessions, and global kill switch `DEMO_LIVE_PROVIDER_KILL_SWITCH`.
4. **ElevenLabs STT Single-Use Tokens**: Ephemeral Scribe tokens issued via `/api/demo/stt-token` without exposing permanent keys.
5. **Single-Use TTS Response Vouchers**: `/api/demo/tts` accepts only single-use `responseId` vouchers generated by `/api/demo/respond`. Arbitrary client text injection is strictly rejected.
6. **OpenRouter Server-Side Inference**: Restricted model allowlist (`openai/gpt-4o-mini`, `anthropic/claude-3-haiku`, `google/gemini-flash-1.5`) with max 160 tokens, 0.2 temperature, 12s timeout, and Zod structured response schema.
7. **Idempotency & Request Locking**: `clientTurnId` UUID validation and `withSessionLock` prevent duplicate turns and race conditions.
8. **Real Database Persistence**: All completed calls, transcript segments, summaries, demo appointments, demo leads, escalations, and CRM activity records are persisted in PostgreSQL via Prisma.
9. **Authenticated Dashboard**: Removed all demo email/password bypasses. Unauthenticated dashboard access redirects to `/login`. Exact bcrypt password matching enforced.
10. **Demo Data Deletion**: Users can delete their demo session records via `POST /api/demo/session/delete`.
